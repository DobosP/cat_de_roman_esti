# Proposed Praf native ownership migration

Valid until: independent review and final V90 implementation supersede this proposal — then treat as history.

This is an unimplemented proposal bound to [the exact graph draft and source](praf-migration-proposal.json).
Adding an ordinary dust node makes native resolution take precedence over the old projected
Praf. Preserve one owner by using the existing native-exclusion mechanism and removing its
now-unused three-target projected neighborhood. No scoring formula or broad proxy change.

Praf, praful and prafului would share the new native ID and one-attempt identity. All other
464 projected entries must remain exact by ID and payload; the expected final count
is 464, down from 465, with 26 domains unchanged. Retain all11 native exact pairs,71 legacy
proxies and four existing audit-only native tuples. Praf is not added to the landscape
native-audit list merely to hide the loss of an old approximation.

The old synthetic public ID and Pământ fallback are retired. This is a deliberate semantic
migration, not an alias between dust and earth. Existing Praf de copt, Lapte praf, soil and
other powder words keep their own identities. Do not add unqualified prafuri as a dust form.
Direct factual links may replace the old rank2 exception with a different hot rank; never
force rank2 just to imitate the approximation. Record all old-target gains and costs.

Fresh games must deduplicate native dust forms, keep guesses nonwinning for tool targets,
retain ordinary clue/resume behavior and withhold hidden answers in typo help. A custom KG
without the new owner no longer receives the retired synthetic Praf fallback, as with the
existing static native exclusions. No deployment-spanning session migration is claimed.
The new concepts have insufficient incoming counts to be hidden targets themselves.

Require independent review before application, exact runtime/history tests and complete
before/after evidence. The actual game engine, sessions, and other words remain subject
to their existing limits and final integration gates.

Cat content V5 source client

From the task worktree, build the standalone Go 1.27.3 module into campaign
scratch. Use a single shared cache across jobs and campaign runs so source
spacing, UTC daily budgets and Retry-After survive a process or run change.

  go -C scripts/content_v5/source-client build -o <scratch>/content-source .
  <scratch>/content-source --cache <scratch>/cache --run <campaign-id> \
    --role factual --fetcher <thread-id> --cache-only \
    --legacy-cache <read-only-v4-cache> https://ro.wiktionary.org/wiki/mas%C4%83

Drop --cache-only to allow new reads. Keep one stable --run ID through retries
and resumes. Set --fetcher to the real script or thread ID. Scope and host
refusals apply to cache hits too. A normal lookup checks cached robots before
the cached content. First-fetch fields are retained on cache hits and across
transient HTTP retries. The first_fetch_origin field distinguishes
legacy from V5 first fetches even when a later V5 response replaces a legacy
transient response. Legacy receipts preserve their original fetched_by_role
and fetched_at without inventing a thread ID. Only a V5 first fetch by a
non-author can satisfy the independent first-fetcher requirement. A client
receipt authenticates neither the caller nor the source claim. Reviewers
still read the source and judge the evidence independently.

One successful lookup prints one JSON receipt. Read its body from
<cache>/<sha256>.body, using the legacy directory if origin is "legacy".
Errors use JSON on stderr with code, message and retry_at when known. For ordinary page reads,
non-200 responses and their bodies remain in scratch for diagnosis. Persistent 429 and 5xx
responses park the host, including cached lookups, until retry_at. The cap counts all network
request starts, including robots, redirects and failed attempts. A cache hit
consumes no reads. Cache misses return cache_miss in cache-only mode.

  <scratch>/content-source --cache <scratch>/cache --run <campaign-id> \
    --role script --fetcher <script-id> --owner-queue
  <scratch>/content-source --cache <scratch>/cache --run <campaign-id> \
    --role policy --fetcher <thread-id> --refuse-host <approved-host> \
    --reason "<one-line terms or crawler policy finding>"

The owner queue returns one entry per refused host in this run, with host,
run, code, reason and UTC timestamp. An interrupted read with no verifiable
receipt appears as source_recovery_required once for that host alongside
the other hosts' entries. Its timestamp is the original request start. The
underlying refusal and interruption state persist under the campaign cache. Use the refusal command for a terms or crawler block found during
policy inspection that the automatic checks cannot recognize. For authorized
policy inspection, a retrieved terms receipt is returned once and the host
then drops for the run. A robots path refusal drops that URL without an owner
queue entry. For port 8077, the documented RO-EDU endpoint uses HTTP and the
V5 contract requires HTTPS. The client reports localhost_protocol_conflict
and queues it on an HTTP URL or failure to complete local HTTPS. It makes no
plaintext request and never disables certificate verification.

Dated Romanian Wikimedia dumps

  <scratch>/content-source --cache <scratch>/cache --run v5-pilot-2 \
    --role script --fetcher <script-id> \
    https://dumps.wikimedia.org/rowiktionary/20261101/rowiktionary-20261101-pages-articles.xml.bz2

The exact allowed filenames are <project>-YYYYMMDD-sha1sums.txt for
rowiktionary or rowiki, rowiktionary-YYYYMMDD-pages-articles.xml.bz2,
rowiki-YYYYMMDD-all-titles-in-ns0.gz and rowiki-YYYYMMDD-redirect.sql.gz.
The dated directory and filename must agree. The host's robots.txt uses the
ordinary policy route. Each file requires one sequential GET, with at least
10 seconds between starts and 20 reads per UTC day across the host. The
initial dated reads require role script. Factual and quality reviewers may
use --cache-only with their own role and ID to revalidate a receipt.

The archive receipt adds dump_checksum.url and dump_checksum.sha256 for
the exact checksum manifest and dump_checksum.sha1 for the archive's
publisher-listed digest. The manifest bytes live in <cache>/<sha256>.body
and the original compressed archive bytes in <cache>/<sha256>.dump, using
their respective hashes. The URL's JSON receipt is stored at
<cache>/<SHA-256 of the canonical URL>.receipt.json. Cache hits recheck the
manifest receipt and bytes, the archive's SHA-256 and the matching published
SHA-1 entry. The archive basename must occur exactly once in the manifest.
Other basenames may occur multiple times. Reviewer use still depends on
the independent parser gate in ADR-0231 decision 5.

A dated file GET consumes the file's attempt even on failure. Keep the
shared host state, outcome receipts and payloads together across runs.
A failed HTTP response keeps its status, headers, first fetch and refusal
code. Its receipt hashes the bytes in <cache>/<sha256>.diagnostic. The
diagnostic retains up to 32 KiB, with body_problem set when the retained
bytes represent a prefix or the full response could not be verified.
Transport failures before HTTP headers have no response body. The host
attempt history pins completed outcome metadata, and cache reuse verifies
its diagnostic bytes.
A cached manifest rejected by the former global duplicate check can be
re-evaluated offline if it is a complete HTTP 200 response and the retained
bytes, response policy and original outcome all verify. The original URL
receipt and diagnostic are retained unchanged. The recovered manifest lookup
adds dump_manifest_recovered_outcome_sha256 and a dependent archive receipt
adds dump_checksum.recovered_outcome_sha256. Both fields pin the original
outcome in host history. Read those manifest bytes from
<cache>/<sha256>.diagnostic and verify the original outcome and body. Other
failed outcomes remain terminal.
A 429 or 5xx still parks the host. The immutable dated URL stays spent
after the breaker expires.
Missing evidence after a recorded attempt fails closed. A crash between
publishing a verified payload and recording its outcome may leave an orphan
payload that the client cannot return. Keep the interrupted state for
investigation and prune orphan payloads in campaign scratch once verified
unreferenced.

Threat model

Remote responses, robots directives and redirects are untrusted. The client
checks the literal HTTPS host and permitted paths before each GET. The bare
Wikidata spelling resolves locally to the approved www spelling. Redirects
are evaluated one at a time and can only stay on the same HTTPS host. The
client disables ambient proxies and sends no credentials, cookies or
referer. Remote DNS answers must be publicly routable candidates, and the
local grant is dialed only at 127.0.0.1:8077. Transport uses system roots,
bounds header size and body reads, and never renders or runs response bodies.
An oversized or partial body is retained with an explicit body_problem and
cannot become evidence. A failed network attempt has no HTTP receipt.

The cache is trusted campaign scratch with one writer and is not a sandbox
for hostile local operators. Do not use a public or shared-writable
directory or point the writable cache into the legacy cache. URL-keyed
receipts bind size and SHA-256 to their body file; a missing or altered body
fails closed. A per-host request reservation is written before any GET and
names the immutable response receipt. If a process stops after that receipt
is saved, the next lookup recovers the URL pointer and applies the response’s
breaker or policy refusal to the original run. If the response receipt is
unavailable, the host parks with source_recovery_required and the other
hosts remain available. Keep the interrupted state for investigation. A stale
.v5-lock parks reads until the operator confirms no client is running and
removes the empty lock directory. Use a local filesystem. First-fetch roles depend on
the orchestrator supplying the real IDs and keeping legacy input read-only.
The client preserves Content-Signal and known crawler and terms indicators.
It cannot interpret arbitrary legal text or detect every challenge page.
Dated dump URLs require a direct complete response, with no redirects or
HTTP content coding. The client requests identity encoding and leaves
archives compressed. A stream writes at most 256 MiB for an archive or
1 MiB for a manifest. Archive requests have a 15-minute deadline.
Manifest requests and early body diagnostics have a 30-second deadline.
The first 32 KiB are checked for recognized terms or crawler markup,
including with missing or misleading Content-Type.
A hash or transport failure discards the temporary payload and retains
only the bounded HTTP diagnostic. The only accepted SHA-1 is the unique exact basename
entry in the corresponding dated Wikimedia manifest, retrieved over
verified HTTPS. SHA-256 pins the exact archive bytes for later review.
The shared cache lock serializes downloads and protects the durable URL
attempt history. Use one trusted cache for the campaign.
Only receipt metadata and a short paraphrase go into tracked docs.

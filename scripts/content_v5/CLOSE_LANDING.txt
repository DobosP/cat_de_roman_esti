V5 receipt-only closeout

From the actual clean local main after the reviewed fast-forward, run
python3 -I scripts/content_v5/close_landing.py --help. Preview first. For
--write provide the pinned cat-doc-check executable. After a successful write,
stage and commit only the four reported files. Do not amend the qualified SHA.

The root-owned manifest carries train_id, baseline, candidate, landed_at,
item_ids, gui_gates, and evidence. Every evidence entry is a scratch-relative
path and SHA-256. Required entries are assembly, build, 4i, reference,
pin-review, http-play, landing-review and, for GUI, unit, full, unit-wrapper,
full-wrapper and full-supervisor. Use original pinned gate result, wrapper
and supervisor JSON. All other entries bind sha (the candidate) and their
relevant baseline, status, verdict or thread IDs. No authored assertion may
substitute for a gate, a source corpus or a replay.

The assembly record gives sorted item_ids, frozen_payload_sha256 keyed by
candidate ID, installed IDs per item, and touched_boards pairs [game, id].
Hash canonical sorted-key compact UTF-8 JSON of each registry payload.
Forms/synonyms specify owner_id, boards board_id, concepts/names node_id, and
edges edge_id. Freeze graph payload in the committed source field names and
board payload with category and difficulty. Lane-specific recipe/caption
closeout needs the corresponding future lane adapter before that lane runs.

For additive Pilot 2 words, assembly.word_link_manifest references the exact
cat-v5-link-install-1 input. Use each canonical authored item SHA-256 in
frozen_payload_sha256 and {node_id, edge_ids} in installed. Include the sorted
native edge IDs from each item's signed list. An identical link signed by both
new endpoints appears in both lists and is counted once in the committed delta.
Closeout replays the source and signed review checks and verifies all fields of
each added node and incident link. The pilot contract fixes the backlog baseline,
and the train's previous main fixes the actual before inventory. Any legacy
puzzle delta must equal the existing generator's result from the final graph.

For a word train, assembly.board_view_diff references the full native
cat-board-view-diff-2 report for the exact committed before and after bundles.
A Cald board is disturbed when its target or ordered top-100 IDs change. A Lanț
board is disturbed when its shortest route changes. Feedback values, captions
and menus are diagnostic changes: replayed over HTTP, never re-blinded.
List every board of disturbed and diagnostic_changes in touched_boards and the
exact HTTP transcript. A cat-board-view-diff-1 report is refused.
If any board is disturbed, assembly.board_reblind references a
cat-v5-board-reblind-1 object with sha, board_view_diff_sha256 and boards.
Each boards row has game, id, view_sha256 (the native after_sha256), thread_id,
verdict (pass) and a retained transcript path/digest reference. The transcript
is a JSON object with those five board, view and role fields plus play, a
nonempty array of action or feedback objects containing actual play text.
Known author, factual, quality, landing and pin threads cannot sign reblind.
Distinct boards may share a critic thread within one blind batch. Each
transcript and play must be distinct.

A disturbed existing Cald board may instead rest on a paired comparison.
assembly.board_reblind_compare references the cat-v5-board-reblind-compare-1
receipt written by cat-board-view-diff --reblind-compare. It replays the blind
critic's typed guesses on the baseline and the candidate. The receipt must bind
sha, baseline, both committed bundle digests and the exact view diff digest.
Each row must name a disturbed Cald board with its exact before and after view
digests and a verdict of win or no-worse. Closeout recomputes the verdict from
the row: win when the candidate is won, else no-worse when candidate_best_rank
is at most baseline_best_rank + k, else worse. A worse or misstated row refuses
the landing. The critic transcript has the same six members as above. Its
verdict is pass or fail, and pass requires the native candidate win. The same
critic-thread, distinct-transcript and distinct-play rules apply across both
receipts. Every disturbed board needs exactly one row in one of the two
receipts. Lanț and the other games accept only the blind pass.

For every disturbed existing Cald board, on either path, both judges sign the
top-100 change. assembly.board_change_reviews has factual and quality
path/digest references to two cat-v5-board-change-review-1 objects. Each has
sha, board_view_diff_sha256, role, thread_id, verdict (accept) and boards. The
boards rows give game, id, before_sha256 and after_sha256 exactly as the view
diff lists them, for every disturbed Cald board and no other. The two reviewer
threads must differ from each other, from every author and from every critic,
including the reblind critics. They may be the judges of the train's words.

Rows with stock_quality (neither build is won) are copied to the landing
receipt as stock_quality_boards, and the queue entry counts them for the owner.
New boards keep their own absolute blind win.
All direct train attachments share the 50 MiB receipt budget. Reusable pinned
source-cache bodies and the dated dump remain outside the train attachment list.
Keep all train evidence in campaign scratch.

The HTTP record binds the exact raw play JSONL with a transcript path/digest.
The reference record binds the corpus (JSON or gzip), independent capture
summary, native replay summary, and named independent expectations_origin.
Each nested path uses the same path/sha256 reference shape. The recapture
summary (cat-v5-independent-recapture-1) carries sha, case_count, reference
and corpus_sha256 from the independent fixed-corpus recapture. The replay
envelope (cat-v5-native-replay-1) carries sha, corpus_sha256 and the original
native report. Both must cover 1,206 cases. The pin reviewer binds
reference_sha256, corpus_sha256, corpus_pin_path, pin_sha, the old/new pin
change list and its own independent thread. The
list has before, after and changes (path, before_sha256, after_sha256, using
null on a nonexistent side). The landing reviewer binds sorted item_ids and
the SHA-256 of assembly, http_play, reference and pin_review.

Threat model
The orchestrator owns the local Git database, evidence and pinned checker.
The checker validates exact bindings and local fast-forward evidence without
changing refs. Reflog data proves the move, not the literal argv. Reviewer
truthfulness and selection of an independent oracle are operator obligations.
The paired comparison can only relax the blind-win rule for a disturbed
existing Cald board whose top-100 change both judges signed. It never covers
a new board, Lanț or another game. Closeout does not replay the guesses. It
trusts the native receipt's numbers after checking its bindings, so the
operator must run the pinned cat-board-view-diff on the committed bundles.
The four local writes roll back after an ordinary error. A killed process
requires inspecting the four exact paths before retry. Use the standard-
library Python 3.12 CLI. The pinned doc checker is Go.

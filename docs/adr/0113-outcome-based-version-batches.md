# ADR-0113: Plan versions around complete player outcomes

- Status: accepted
- Date: 2026-09-06

## Context

The owner requested continued improvements to the existing games and their connections,
with meaningful content expansion included when starting each version. V75–V81 split
ingredient repairs, reviews and target promotions into small versions, repeatedly paying
integration and review costs. File counts and grammatical aliases overstated visible growth.

## Decision

Start each version with a bounded batch and an explicit baseline, player problem, proposed
outcomes and acceptance evidence. Keep refactoring purposeful: it should remove a known
obstacle to correctness, usability or content extension. Assess the six-game backlog across
gameplay, Romanian recognition, feedback, difficulty, accessibility, reliability and beta
readiness; select a coherent scope rather than changing every area superficially.

Content versions aim to deliver several new playable rounds together with the connection,
vocabulary or feedback repairs they require. Review enough independent candidates to allow
rejections without reducing every version to one target. A necessary critical fix may stand
alone, with its narrower outcome explained. Quantities are planning targets, never grounds
to weaken the critique rubric, invent synonyms, add filler edges or promote an unfair round.

Use parallel candidate research, independent critiques and focused development checks.
Run the required integration gates on the assembled candidate; repeat checks when edits,
failures or unresolved concerns invalidate their evidence. Preserve existing content,
privacy, determinism and session-bound requirements. This decision changes batching and
reporting, not the content approval contract or release authorization.

At completion, report baseline-to-candidate additions, removals and changes for canonical
concepts, graph connections, accepted forms, curated rounds by game and derived boards.
Report promotions and runtime eligibility separately from raw stock. An alias is not a
verified synonym; list genuine synonyms only with explicit linguistic review. Include
player-visible fixes, deferred candidates, checks actually run and remaining release gates.
Use reusable delta tooling and concise reproducible evidence; large audit dumps and test
counts are not measures of enjoyment or content value.

## Consequences

V82 applies this policy to a batch of familiar food targets over the reviewed V81 graph,
including a fresh Cozonac review. Its initial target is four to eight approved, selectable
rounds, subject to independent critique. It also introduces reusable content delta reporting.
Later versions choose their own coherent batch from the current backlog. Public beta remains
anonymous, human playtesting remains unverified, and landing means merging to local main.

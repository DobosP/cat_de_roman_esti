# V90 Alchimie action recovery

A lost committed combine, hint or reset now causes one owned GET without replaying the
mutation. Failed verification leaves persistent read-only retry and locks board mutations.
A restored inventory or terminal result comes from the current server state. The paid hint
also becomes resumable through one bounded public cue; no second hint charge is needed.

[ADR-0136](../../../adr/0136-reconcile-uncertain-alchimie-actions.md) records ownership,
privacy and the exact cue lifecycle. [Preservation checks](preserved-behavior.json) bind
fourteen byte-identical baseline files: the shared owner/transport, all five other game
screens, active/resume/score hooks, session store and request handling. No scoring formula,
recipe-generation helper, selector, TTL, request limit or shared action helper changed.

## Before and after

[Baseline proof](baseline-proof.json) contains four complete actual browser/BFF captures
against clean V89 main `190d7fd`. Each POST committed, then only its response was replaced
with HTTP 503. The browser made zero verification GETs: a new discovery stayed absent,
reset left the previous progress visible, the first paid clue was lost, and a final win had
no result card or local score receipt. GET contained no clue fields even after `hints_used`
increased. The completed four-case baseline ran before implementation and passed in 15.4 s.

The server now exposes optional `earned_hint` with exactly `hint`, `hint_kind`, `hint_output`
and `message`, copied only from freshly server-authored public hint fields. One cue replaces
itself on a later paid hint. GET, rejected actions and free repeated pairs preserve it;
a new unique combine (productive or empty), reset and the resulting terminal win clear it.
The defensive no-forward path neither charges again nor retains a “none” cue. Output hints
carry only a non-target label; pair hints contain two already-owned concepts. No hidden
output id, target id, private route, recipe map or hint history is added.

The browser restores earned pair selection and renders the cue once. GET does not expose
the lost combine's transient verdict, so it gives neutral synchronization feedback instead
of claiming an empty reaction or inventing newly discovered ids. Ordinary successful empty
combines retain their existing change-one-ingredient guidance and free-repeat behavior.
A different saved pointer prevents the old action or old response from taking ownership.
An owned 404 returns to setup; a late 404 cannot remove another saved game. Unmount preserves
uncertain progress for normal resume. A recovered win uses the existing single score receipt.

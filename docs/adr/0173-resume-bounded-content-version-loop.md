# ADR-0173: Resume a bounded local content version loop

Valid until: a later owner decision supersedes the standing loop request — then treat as history.

Date: 2026-10-06
Status: accepted; discovery continuation clarified by ADR-0174

## Decision

Continue V1.5 in finite reviewed iterations under the owner's renewed request. Stay in that
version until a nonempty meaningful improvement passes its exact independent reviews,
supported content rails, applicable native/game/history gates and assembled review, then
the coordinator lands it in local main. Start a later version only from the actual verified
main merge receipt. Keep candidate budgets finite; replan after at most three substantive
revisions or two unchanged failures. There is no shipment quota.

## Context / why

The accepted V1.4 baseline and V1.5 research/blueprint are now on local main. V1.5 is not
qualified content: the exact Breloc/Pâlnie one-link hypotheses remain below the existing
incident4/same-category2 new-node guard. Research acceptance alone cannot clear adoption.
The owner renewed the recurring loop after the earlier stop decision in
[ADR-0137](0137-finish-v91-and-stop-iteration-loop.md).

This supersedes ADR-0137 only for renewed V1.5-and-later iteration authority. Its historical
V91 completion and all verification, local-only and preservation boundaries remain.

## Consequences

Use a task branch/worktree from the landed baseline, preserve earlier exact evidence and
held/rejected records, and keep shared main clean. The content skill and
[ADR-0156](0156-two-track-content-growth.md) still separate research from refinement and
installation. Author-independent factual and quality judgments remain required.

Resource recovery does not release a native campaign hold. Source/evidence/review preparation
can proceed only within the admitted finite budget; toolchain/build/install, WSL/Docker,
PostgreSQL, full-suite, browser and model campaigns await the actual owner-agreed execution
window and coordinator admission. Do not weaken editorial/connectivity/history/session gates.

The coordinator owns acceptance, resource/phase state and actual main landing. A worker
preserves exact progress packets and requests landing only after current qualification is
fully green. Scheduler identity and machine-specific handoffs remain outside this repository.
This request permits no push, deployment, deletion or production account activation.

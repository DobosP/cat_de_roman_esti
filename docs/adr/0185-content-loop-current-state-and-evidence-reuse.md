# ADR-0185: Current-state content iterations and evidence reuse

Date: 2026-10-08
Status: Accepted

## Context

The owner resumed Linux content work after the Windows handoff and requested loop improvements. V1.7's accepted leafă input is unfinished. Windows changed runtime dependencies and managed SPA handling while leaving Source6 content bytes intact; cutting-board R2 remains research only. Repeated chronological handoffs, assumed artifact shapes and duplicated archives increased iteration time and obscured the next action.

## Decision

1. Keep one concise current handoff: current revision, selected content, actual milestone, blocked prerequisites and one next executable step. Immutable historical receipts remain linked by path and exact hash; their judgments are never rebound to new bytes.
2. Inspect the existing native CLI and actual artifact schema before constructing consumer checks. RuntimeHashes is a list of path/SHA records; source bindings are a map. Verify complete membership and identities using those contracts. No generic replacement runner or schema workaround is introduced.
3. Refresh executable, dependency, embed and metadata bindings only when they change. Reuse unchanged semantic records and completed cases within their actual scope. Fresh runtime audits, same-role finals and all required installation/release gates remain mandatory after affected changes.
4. Prioritize finishing the bounded selected leafă adoption before selecting new installation breadth. Preserve Tocător's useful Windows research and explicit proxy migration questions for a separately justified scope; there is no shipment quota.
5. Reference an already durable byte-exact archive by its path/hash/member manifest instead of nesting another copy in every subsequent packet. Preserve all new outcomes, failure packets and source provenance. Explicitly dispatch idle agents, reserve time for independent review and retain original campaign deadlines.

## Unchanged boundaries

Independent factual and quality judgments, supported transactions, private answers, historical saves, deterministic bounded sessions, graph/target/World critique thresholds, fresh resource admissions and exact assembled acceptance remain required. No failed guard or clock is reset, no omitted test is called passed, and no source checkpoint is called a content release. Human stop/pause controls the heartbeat. Main remains clean; further push and deployment require explicit authorization.
